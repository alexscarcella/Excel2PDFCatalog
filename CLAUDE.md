# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Excel2PDFCatalog is a Windows/macOS desktop tool (Tkinter/`ttk` UI + ReportLab PDF engine) that converts a product-list Excel file into a printable PDF catalog. The UI is a tabbed `ttk.Notebook`, bilingual (Italian/English, switchable at runtime), and stdlib-only — no UI dependency beyond `tkinter`. It ships as a source app and as PyInstaller-built standalone executables (see `.github/workflows/build.yml`).

## Commands

```powershell
# setup
python -m venv .venv
.venv\Scripts\activate
pip install -r app/requirements.txt

# run
python Excel2PDFCatalog.py

# tests (stdlib unittest, no extra dependency)
python -m unittest discover -s tests -v
# single test module
python -m unittest tests.test_config_utils -v
```

`tests/` has a minimal `unittest` suite for `config_utils.py` (load/save fallback, `language` round-trip), `images_utils.py` (`load_image_path`), `build_PDF.py` (`test_build_pdf.py` — price formatting, markup escaping, trailing-row flush, layout params applied at build time), `i18n.py` (`test_i18n.py` — translation fallback, IT/EN key parity, language hooks, `COLOR_GROUPS` coverage), and `excel_config.py` (`test_excel_config.py` — default fallback, save/load round-trip, typed accessors) — no framework beyond stdlib is required. There is no lint or build tooling configured for local development, and no CI running on push — the only workflow is a manual `workflow_dispatch` PyInstaller packaging job for releases. There's no rendering-level coverage for the Tkinter side (`ui_interface.py`); validate changes there by running the GUI, switching language, and generating a PDF against `example_excel/Product list example.xlsx`, checking `logs/app.log` for warnings/errors.

## Architecture

**Core modules, coupled through shared mutable state in `app/config_utils.py`:**

- `Excel2PDFCatalog.py` — entrypoint: calls `config_utils.load_config()` then `ui_interface.build_UI_and_GO()`.
- `app/config_utils.py` — the single source of runtime state. Module-level globals (`language`, `excel_file`, `txt_intro_file`, `title`, `subtitle`, `footer`, and the dicts `colors_dictionary`, `path_dictionary`, `flags_dictionary`) are written directly by the UI and read directly by the PDF builder — there's no explicit object passed between them. `load_config()`/`save_config()` (de)serialize these globals to `config.json` in the working directory; `load_config()` also calls `i18n.set_language()`. `COLOR_DEFAULTS`/`FLAG_DEFAULTS` snapshot the defaults (before `load_config()` mutates the dicts) for the UI "reset" buttons. `path_dictionary` values are `pathlib.Path` in memory, stringified on save.
- `app/ui_interface.py` — `build_UI_and_GO()` builds a `ttk.Notebook` window (tabs: Sources / Catalog / Options / Colors / Excel columns) plus a persistent bottom bar (status label + "Save config" + accent "Save & build PDF") and a menu. Still imperative and still nested-closure style: file/folder pickers, text fields with `trace_add` bindings, per-flag `Checkbutton`s from `flags_dictionary`, per-color rows from `colors_dictionary` (grouped by `i18n.COLOR_GROUPS`, each row a swatch + hex `Entry` + ↺ reset). Callbacks write straight into `config_utils` as before. The Options tab also has a "Layout" section with numeric `Entry`s for `MARGIN` / `CARD_BORDER_WIDTH`, and the "Excel columns" tab (`_build_excel_columns_tab`) edits the `[Excel]` mapping + `LOCALE` (an editable `ttk.Combobox` fed by `excel_config.COMMON_LOCALES`); both write into `app/excel_config.py`'s dicts, persisted by `config_utils.save_config()`. `_init_style()` forces the `clam` theme + platform font + named styles; `_set_window_icon()` sets the Tk window/taskbar icon best-effort from `assets/icon/` (any failure is only logged). Validation is inline in the status bar (`_validate_and_report()` / `_collect_problems()`); the module-level `check_parameters()` is kept (unchanged, dialog-based) for external callers. "Save & build PDF" runs `build_PDF.build_pdf()` on a **worker thread** (`_run_build_with_progress()`): a modal `Toplevel` — centered on the app window via `_center_over_root()`, not the monitor — shows a determinate 0–100 % `ttk.Progressbar` + percentage label and, under it, a read-only `tk.Text` + `ttk.Scrollbar` that logs `[i/n] category › company › product` for each row as it is processed. Progress events come from `build_pdf(progress_cb=...)` through a `queue.Queue` drained on the Tk thread by a `root.after` `pump()` (no Tk calls off-thread). On success `_show_build_done_dialog()` (also centered) shows the PDF path with **Open file** / **Open folder** (`os.startfile` / `open` / `xdg-open`) / **Close**.
- `app/i18n.py` — dependency-free, Tk-free bilingual layer (IT/EN). `t(key, **kw)` (fallback: EN, then the key itself), `set_language()` (fires every `on_language_change()` hook — each tab builder registers one that re-`config`s its widget text), `clear_hooks()` (called at the top of `build_UI_and_GO()`), `detect_default()` (from `locale`), `field_label()`/`field_hint()` (translated labels for dict keys, falling back to `.replace('_',' ').capitalize()`), plus `TRANSLATIONS`, `COLOR_GROUPS`, `FLAG_ORDER`. Only *display strings* are translated — dict keys stay English (they are serialized and read by `build_PDF.py`).
- `app/excel_config.py` — dependency-free, Tk-free layer over `Excel2PDFCatalog.config` (INI). Holds the `[Excel]` column mapping, `[Layout]` (`MARGIN`, `CARD_BORDER_WIDTH`) and `[System]` (`LOCALE`) in the module dicts `columns` / `layout` / `system`; `load()` (per-key fallback to hardcoded defaults, never fatal) / `save()` (hand-rolled serializer that keeps the section comments) round-trip them. Like `config.json`, it reads/writes a **writable copy** at `writable_path("Excel2PDFCatalog.config")`, seeded from the bundled file on first run (from source the two paths coincide). Typed accessors (`all_columns()`, `required_column_names()`, `margin_cm()`, `card_border_width()`, `locale_name()`) are what `build_PDF.py` consumes. `COLUMN_KEYS` (ordered `(logical, ini_key, default, required)` tuples) and `COMMON_LOCALES` (list feeding the locale combobox) drive the "Excel columns" tab. Auto-`load()`s at import.
- `app/build_PDF.py` — PDF assembly with ReportLab. At **import time** it registers the custom TTF font from `fonts/` and calls `_init_excel_mapping()` / `_init_layout()` / `_init_locale()` — which pull the column mapping, page geometry (margin → `Frame`s + `PageTemplate`s) and locale from `app/excel_config.py`. Those three `_init_*` run **again at the top of `build_pdf()`**, so edits made in the UI take effect on the next build without an app restart. `build_pdf()` reads the Excel file with pandas, iterates rows, and appends ReportLab Flowables to a module-level `story` list. It takes an optional `progress_cb` and **returns the output PDF path**; Excel-read and `doc.build()` failures `raise` (no `sys.exit()`) so the UI can report them. `progress_cb` is called via `_emit_progress()` with a dict: `phase="rows"` (one per Excel row, `fraction` 0→0.9, plus `index`/`total`/`category`/`company`/`product`), `phase="render"` (0.9→1.0, mapped from ReportLab's `setProgressCallBack` `SIZE_EST`+`PROGRESS`), `phase="done"` (`fraction` 1.0). An exception raised inside `progress_cb` is logged, never fatal.

**Two distinct config files — do not conflate them:**
- `Excel2PDFCatalog.config` (INI) — Excel column mapping (`XLS_COLUMN_*` + `XLS_BADGE`), `[Layout]` (`MARGIN`, `CARD_BORDER_WIDTH`), `[System]` (`LOCALE`). Owned by `app/excel_config.py` (not read directly anywhere else). UI-editable (Options "Layout" section + "Excel columns" tab); persisted by `config_utils.save_config()` alongside `config.json`. In a frozen build the editable copy lives under `writable_path()`, seeded from the bundled read-only file.
- `config.json` (JSON, generated) — UI/runtime state: `language`, title/subtitle/footer, colors, folder paths, boolean flags. Written by `config_utils.save_config()`, read by `config_utils.load_config()`.

**PDF layout model (ReportLab):** the document uses four named `PageTemplate`s registered on one `BaseDocTemplate` — `Cover`, `Body`, `Category`, `Matrix_3x3` — each with its own `onPage` canvas callback (`cover_on_page`, `body_on_page`, `category_on_page`, `matrix_3x3_on_page`) that paints background color and header/footer text from `colors_dictionary`. Pagination is driven by pushing `NextPageTemplate(...)` + `PageBreak()` onto `story` as the Excel rows are scanned. Products are grouped into a 3-per-row grid: `raw_1x3_items`/`raw_1x3_counter` accumulate up to 3 product tables, flushed via `flush_1x3_row()` into a `KeepTogether` table row — a new `Category` title page is emitted whenever the category column value changes, and (if `BREAK_PAGE_COMPANY` is set) a company divider page whenever the company column value changes.

**Product images:** looked up in `PRODUCTS_IMAGES_FOLDER_PATH` via `images_utils.load_image_path()`, which tries `.png`/`.jpg`/`.jpeg` in that order against the filename from the Excel image column. If missing, falls back to a procedurally generated placeholder blob image (`images_utils.generate_image()`, written under `tmp/`) when `GENERATE_RANDOM_PRODUCTS_IMAGE` is set, otherwise to `PRODUCTS_IMAGES_FOLDER_PATH/default.png`.

**Logging:** shared `AppLogger` in `app/logger.py`, rotating file handler at `logs/app.log` (1MB × 5 backups) plus console. Use `logger.info/warning/error` — this remains the primary debugging surface for the ReportLab/Tkinter code paths that the `tests/` suite doesn't cover.

**Path resolution (`app/paths_utils.py`):** every filesystem path in the app goes through this module instead of being built directly, because the same code must work running from source and as a frozen PyInstaller bundle (onedir on macOS). `resource_path(rel_path)` resolves *read-only bundled* assets (`Excel2PDFCatalog.config`, `fonts/`, `assets/icon/`, `example_excel/`, `example_catalog/`, `img_products/`, `img_general/`) — from `cwd` when running from source, from `sys._MEIPASS` when frozen. `writable_path(rel_path)` resolves *runtime-writable* files (`config.json`, `logs/app.log`, `tmp/`, `crash.log`, `startup.log`) — from `cwd` normally, but from a per-user data dir when frozen. `Excel2PDFCatalog.config` is deliberately in **both** lists: `excel_config.py` reads the bundled copy via `resource_path()` only to seed a writable copy at `writable_path("Excel2PDFCatalog.config")`, which is thereafter the one read and written. The per-user data dir when frozen is: `~/Library/Application Support/Excel2PDFCatalog` on macOS (a `.app` launched from Finder/Dock has its home directory as `cwd`, not the app bundle) and `%LOCALAPPDATA%\Excel2PDFCatalog` on Windows (an `.exe` can inherit an arbitrary `cwd` from a shortcut's "Start in"). `Excel2PDFCatalog.py` installs a global `sys.excepthook` that writes tracebacks to `writable_path("crash.log")` before any other import, since a windowed PyInstaller build has no visible stdout/stderr. When adding a new file path anywhere in the app, route it through one of these two helpers rather than joining against `cwd` or `__file__` directly.

**`build_pdf()` internals:** it first re-runs `_init_styles()` + `_init_excel_mapping()` / `_init_layout()` / `_init_locale()` (picking up any UI edits to colours and to `Excel2PDFCatalog.config`), then the per-row loop is decomposed into helpers in `app/build_PDF.py` — `_clean_row_fields` (fills/logs missing Excel cells), `_format_price`, `_insert_category_page`/`_insert_company_page` (pagination side effects on the module-level `story` list), `_load_product_image` (also sanitizes the image filename from Excel via `Path(...).name` to prevent path traversal), and `_build_product_card` (builds the ReportLab `Table` for one product; card border thickness from `excel_config.card_border_width()`; **every** card row except the image is a fixed height — `NAME_ROW_HEIGHT` (~1.8 cm) for the product name, `SIZE_ROW_HEIGHT` (~0.95 cm) for the `Formato`/price row, 0.5 cm for the company — so neither a long name nor a wrapping `Formato` value (e.g. "Confezione da 10") can grow the card past its 3×3 grid cell and deform the rounded border; the name gets near-zero horizontal padding so it flows onto 3–4 full-size lines, and name, `Formato` and price are each wrapped in a `KeepInFrame(mode='shrink')` that scales the text down only if it still overflows its fixed cell. `IMAGE_SIZE` (in `_load_product_image`) is 4.1 cm to keep the total within the cell). `build_pdf()` itself just orchestrates these per row.

## Cross-cutting gotchas when changing things

- Renaming a `colors_dictionary` / `path_dictionary` / `flags_dictionary` key requires updating the default in `config_utils.py` **and** every direct reference in `build_PDF.py` (styles, canvas fills). `ui_interface.py` generates its controls by iterating these dicts, so new keys need no UI code — they render with `i18n.field_label()` (a `field.<KEY>` translation, falling back to `.replace('_',' ').capitalize()`). For a new color key also add it to a group in `i18n.COLOR_GROUPS` (ungrouped keys still show, under "Other colours"); add `field.<KEY>` / `hint.<KEY>` strings to **both** `it` and `en` in `i18n.TRANSLATIONS` (the `test_i18n` suite asserts key parity).
- Adding/renaming an `Excel2PDFCatalog.config` key: edit `COLUMN_KEYS` / `LAYOUT_DEFAULTS` / `SYSTEM_DEFAULTS` in `app/excel_config.py` (default + logical name) **and** the mapping in `build_PDF.py._init_excel_mapping()` / `_init_layout()` if it feeds a module constant. The "Excel columns" tab and Options "Layout" section iterate `excel_config.COLUMN_KEYS` / read the `layout` dict, so a new key needs only `field.<KEY>` / `hint.<KEY>` strings in **both** `it` and `en` of `i18n.TRANSLATIONS` (`test_i18n` asserts parity). New `tests/test_excel_config.py` covers load/save.
- `build_PDF.py` does substantial work at **module import time** (registering the font) — but the column mapping, page geometry and locale are (re)computed by `_init_excel_mapping()` / `_init_layout()` / `_init_locale()`, which run both at import **and** at the top of `build_pdf()`. If you add a config-derived module global, wire it into one of those `_init_*` so UI edits still apply without a restart.
- Never hardcode a path relative to `cwd` or `__file__` for bundled or runtime files — use `paths_utils.resource_path()` / `paths_utils.writable_path()` (see Architecture above) so behavior stays correct in the PyInstaller-frozen builds, not just when running from source.
- App/window icon lives in `assets/icon/` (`icon.ico` Windows, `icon.icns` macOS, `icon_*.png` for the Tk window; `make_icon.py` redraws all of them procedurally with Pillow — run `python assets/icon/make_icon.py`). `.github/workflows/build.yml` passes `--icon` and `--add-data "assets/icon..."` per platform, and `ui_interface._set_window_icon()` loads `icon_256.png` / `icon.ico` at runtime via `resource_path()` — keep those three in sync if you rename or move the icon files.
